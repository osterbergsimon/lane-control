# What lane-control does that Orca now does too (ORC-1)

Date: 2026-11-25. Issue lc-5rz. The owner's words, the same day: "lets use orca where we can". The doctrine that came
of it is in the README ([Doctrines](../../README.md#doctrines), "Use Orca where we can"). This page is the audit behind
it: each piece of lane-control that overlaps something Orca has or now ships, and whether to replace it, wrap it (keep
a thin call into Orca) or keep it; one row is new work instead, since Orca has nothing to call. It changes no code; the
owner picks what to replace, and each replace or wrap row has its own issue.

## How to read it

Sources, all read-only:
- **[help 268]** / **[help 274]**: `orca-ide <command> --help` on Orca 1.4.268, and again on 1.4.274 after the owner's
  upgrade the same day. Read: the top-level help; `pair`; `host list|rm`; `environment add`; `vm recipe doctor`;
  `vm env doctor`; `account add|list|select`; `status`; `diagnostics memory`; `automations create|list|runs|watch-pr`;
  `orchestration send|check|worker-start|worker-list|worker-show|gate-create`; `skills install|update|share|installed`;
  `agent hooks|installed`; `worktree ps`; `worktree create`; `project setup-clone|setup-existing-folder`;
  `workspace cleanup preview`; `screenshot`; `full-screenshot`; `set media`; `set device`; `tab create`; `serve`.
- **[guide]**: `orca-ide skills get orchestration` (and its references) and `skills get orca-cli`, version-matched, on
  1.4.268 and 1.4.274; `agent-context`.
- **[notes 2xx]**: the GitHub release notes of v1.4.269, 271, 272, 273 and 274 (`gh release view`). There is no v1.4.270
  release. A PR number is Orca's.
- **[source 2xx]**: Orca's public source at that release tag, read with `gh api`: the worker stop notice's wording
  (`worker-turn-stop-wording.ts`, v1.4.274), the send flags (`orchestration-send-flags.ts`, v1.4.271 and v1.4.272) and
  the orchestration guide (`skill-guides/orchestration.md`, v1.4.271 and v1.4.272).
- **[repo]**: lane-control's own files.

Nothing was run against Orca except `--help`, `skills get|list`, `agent-context` and `orca-ide settings` (to see that no
such command exists); nothing was created, paired or changed. So no row is "verified" by a run: what a help page or a release note says is marked as such, and what neither
says is **unclear**. **272+** marks a feature that is only in 1.4.272 or later (this machine has run 1.4.274 since the
upgrade); 269 and 271 features are marked with their version too.

## Summary

23 rows: 1 replace, 7 wrap, 14 keep and 1 new work (row 15 keeps its slots, CPU and CI limits and counts as a wrap for
its memory part). The machine coordinator's own scripts are audited separately below. What Orca now covers well is the health of a *worker*: from 1.4.269 to 1.4.273 it learned to tell the
coordinator when a worker stops without reporting, goes quiet, hits a usage limit, exits or never got its brief. What
Orca does not cover is most of the *machine* and the *owner's budget* (heavy-work slots, a shared memory pool, CPU and
CI limits, weekly ceilings, presence; its only memory limit is an opt-in cap per terminal, row 15), an *idle
coordinator* with work pending, and the reverse tunnel for a box behind NAT. Those stay ours.
